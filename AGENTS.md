# Documentation

Write documentation in English. Use [ASD-STE100](https://www.asd-ste100.org/about_STE.html) as a guide, with natural wording for software readers. This is a relaxed style, not a claim of formal compliance.

- Lead with the purpose, then give the steps and limits.
- Use common words, active voice and consistent technical names.
- Give each sentence one main idea. Aim for 20 words in instructions and 25 words in explanations.
- Keep paragraphs short, but connect related ideas. Avoid sentence fragments.
- Keep only facts needed to use, maintain or verify the current system.
- Preserve security constraints, compatibility limits, source attribution and unverified acceptance criteria.
- Explain each rule in one place. Link to it elsewhere.

Do not add rigid vocabulary checks or padding to satisfy sentence limits. Read the result for clarity and flow.
